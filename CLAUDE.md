# Agent instructions: SHIFT (GitHub Game Off 2026)

This repo is Daniel's entry for **GitHub Game Off 2026** (theme **SHIFT**): ONE browser game that is a curated collection of small games, each a different take on SHIFT, behind a shared hub. One Godot project, one export, one itch.io page.

Deadline: **Dec 1 2026, 13:37 PST** (2026-12-01T21:37:00Z). The game must be in this public GitHub repo and submitted on itch.io by then. Most of the work must happen during November. AI-assisted work is allowed and must be disclosed on the submission page.

An AI team builds it on an hourly schedule: see `studio/README.md`. Anyone working here, human or agent, follows these rules.

## The MicroGame contract (shared/micro_game.gd has the details)
- `games/<slug>/game.tscn` root script `extends MicroGame`. Arcade sets `slug` and `autoplay` and calls `begin()`.
- The game calls `finish(score, won)` once per round. Arcade records the score, shows the shared result card (retry / hub) and handles restart. No per-game title or game-over screens: the hub is the title screen.
- `autoplay == true`: a simple bot plays with real inputs and reaches `finish()` within 60 s of game time.
- Pure rules go in `rules.gd` (no nodes, no autoloads) and are asserted in `selftest.gd`, which prints `SELFTEST OK`.
- `game.json`: `title`, `tagline`, `controls`, `accent` (hex), `genre`, `shift` (how it reads the theme), `status` (`draft` → `shipped` → maybe `cut`), `slot` (hub order).
- Reserved keys owned by Arcade: **Esc** (back to hub), **P** (pause), **M** (mute). Read game input in `_unhandled_input` or by polling so the shared HUD buttons get clicks first.

## Hard rules
1. **Godot 4.7, GDScript, static typing.** No Godot 3 APIs (`yield`, `KinematicBody2D`, `instance()`, `rand_range`). See `.claude/skills/godot-web-gdscript`.
2. **Compatibility renderer, no threads** (`variant/thread_support=false`). No `Thread`, `WorkerThreadPool`, `AudioStreamGenerator`.
3. **Keyboard AND touch/mouse** in every game. Controls are free per game, but a phone player must be able to play with touch alone.
4. **1280×720 canvas, letterboxed.** Lay out for exactly that (`view_size()`).
5. **The web font has no symbols.** The exported game only has Godot's fallback font: Latin text and basic punctuation. Arrows, shapes, box drawing and emoji render as empty boxes in the browser (desktop runs hide this). Draw shapes or write words. `scripts/glyph_lint.py` enforces it.
6. **Assets: generate, don't download.** `_draw()`, `Polygon2D`, shaders, `Synth` for audio. Any file asset must be original or CC0 and listed in `games/<slug>/CREDITS.md`. Keep `index.pck` small (under 20 MB in total).
7. **Saves go through `Save`** (`user://` = IndexedDB on the web). Never write files directly.
8. **Ownership:** a game's code lives only in `games/<slug>/`. `shared/`, `hub/`, `project.godot` and `export_presets.cfg` belong to the Platform Engineer role. Never edit `games/_template/` while building a game.
9. **A game is shippable when** `./scripts/check.sh <slug>` prints PASS, its screenshots look right, and its DESIGN.md acceptance checklist passes. Never claim a check passed that you didn't run.

## Commands
```bash
bash scripts/ensure_godot.sh             # find or install Godot into .tools/ (prints the path)
./scripts/new_game.sh <slug> "<Title>"   # scaffold games/<slug> from games/_template
./scripts/check.sh <slug> | hub | all    # THE GATE: glyph lint, import, smoke, autoplay round, selftest, hub tour
./scripts/shots.sh <slug>|hub [frames]   # real-renderer screenshots → .tools/shots/ (needs xvfb-run)
python3 scripts/registry.py [--check]    # rebuild games/registry.json from game.json "status": "shipped"
./scripts/export_web.sh                  # one HTML5 build of everything → build/web/ (needs web templates)
node scripts/browser_check.mjs           # boot build/web in headless Chromium, assert no errors, screenshots
./scripts/zip_for_itch.sh                # dist/shift-web.zip for itch.io
./scripts/serve.sh                       # http://localhost:8000
bash scripts/git_unlock.sh [--now]       # move aside .lock files git couldn't delete (Claude sandbox on Daniel's PC)
```
`GODOT=/path/to/godot` overrides the binary (default: `.tools/godot`, then `godot` on PATH).
`check.sh all` takes a few minutes with many games; in a shell with a time limit run it in the background (`nohup ./scripts/check.sh all > .tools/check-all.log 2>&1 &`) and poll the log.

## Style
- One script per responsibility; keep each script under ~300 lines.
- Tunables as SCREAMING_CASE constants at the top of the file.
- Signals over node-path reaching.
- Commit subjects: `Add <Title>`, `<Title>: <change>`, `Hub: <change>`, `Shared: <change>`, `studio(R####): <summary>`.

## The AI studio (hourly)
The procedure every scheduled run follows is `studio/procedure.md`; the roles are in `studio/roles/`. Two rules apply to everyone, scheduled or not:
1. Read `studio/HANDOVER.md` first. Its "Next run should" list is the default plan.
2. Before ending a session that changed anything (including failed or partial ones), rewrite `studio/HANDOVER.md`, append to `studio/LOG.md`, and release the lock in `studio/state.json`.

Daniel steers through `studio/INBOX.md` (any note, triaged at the start of every run), GitHub issues he opens on this repo (`scripts/issues.py`), and `studio/state.json` (`paused`, `phase_override`).

## Scheduled tasks (kept in git)
Each scheduled task for this repo is defined in `studio/schedules/` as `<name>.json` (settings) and `<name>.prompt.md` (exact prompt). Git is the source of truth; `studio/schedules/README.md` has the sync rules. If you change a scheduled task, update its files in the same session and commit with a subject starting `schedules: sync`.
